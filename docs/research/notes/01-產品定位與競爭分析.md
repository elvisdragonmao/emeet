# 產品定位與競爭分析 筆記

## 重點整理
- 會議助理市場已經很擁擠，Otter、Fireflies、Granola、Fathom、tl;dv、Notion、Zoom、Teams 都已經在做轉錄、摘要、行動項目和會議搜尋。
- 「錄下來、整理摘要、會後查詢」已經不是很強的差異化，只能算基本盤。
- 比較有空間的是 macOS 原生、低摩擦、偏個人使用的即時會議副駕，尤其是在會議進行中幫使用者判斷「現在該怎麼說」。
- 競品有些也有會中聊天或 live assist，但很多是綁在平台、bot、CRM、團隊部署或會後流程裡，不是專注在使用者當下的戰術回應。
- 最適合第一版切入的場景不是一般會議，也不是線上課堂，而是高風險外部對話，例如銷售探索、客戶成功、顧問會議、產品 demo。
- 面試輔助雖然功能上相似，但如果主打真實面試中的即時答案輔助，會有公平性、同意和聲譽風險，不適合當公開定位。

## 對專題的影響
- 專題展示時，應該把產品說成「即時對話輔助工具」，不是另一個會議筆記工具。
- 轉錄和摘要要做，但它們是支撐即時建議的基礎，不是產品主角。
- 差異化應該放在三件事：即時回覆建議、追問問題、模型/供應商可切換。
- 如果目標是銷售或高風險外部會議，功能設計就會更聚焦：問題偵測、異議回應、需求釐清、下一步確認。
- macOS 原生加上無 bot/低 bot 體驗，可以避開一部分「會議機器人加入會議」造成的尷尬和平台限制。
- 隱私與同意要設計成產品優勢，不能讓使用者覺得這是偷偷錄音或偷偷分析別人。

## 可以採用的做法
- 產品一句話定位可以寫成：一款 macOS 原生的高風險外部對話即時會議副駕，把即時逐字稿轉成回覆建議、追問問題和下一步行動。
- MVP 先做這些功能：音訊擷取、即時逐字稿、問題偵測、「What should I say?」、「Follow-up questions」、即時 AI 聊天框、會後摘要與行動項。
- 可以讓使用者在會前輸入簡短背景，例如客戶資料、會議目標、議程、職缺描述或產品簡介，讓建議更有脈絡。
- 競品比較不用追求每個功能都對齊，反而要強調我們的核心互動比較快、比較貼近會中的壓力場景。
- 模型層要做成 provider abstraction，讓不同任務可以走不同模型，例如本機 STT、雲端摘要、回覆建議、歷史檢索。
- 對外展示時可以用三個情境：銷售探索通話、客戶成功升級通話、創辦人/產品負責人的外部合作會議。

## 風險與待確認
- 不能把「支援外部 API」當成唯一賣點，因為很多競品已經有 API、MCP、CRM 或 connector。
- 如果主打所有會議，需求會變太散，MVP 也會很難評估成功與否。
- 如果主打面試即時輔助，容易被解讀成作弊或不透明監聽，建議只保留在模擬面試或會後整理情境。
- 要確認使用者到底是學生、業務、顧問、創業者還是一般知識工作者，因為提示詞、介面和評估指標會不同。
- 競品定價和功能變化很快，正式簡報前要再更新一次市場資料，但畢業專題的重點應放在可展示的核心互動。
- 隱私設計要包含可見錄製狀態、資料刪除、是否送雲端、是否保留逐字稿，否則產品信任感會很弱。
