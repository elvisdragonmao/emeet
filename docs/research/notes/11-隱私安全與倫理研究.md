# 隱私安全與倫理研究 筆記

## 重點整理
- 這篇的核心不是「技術上能不能錄」，而是「在什麼條件下才應該錄、轉錄、摘要和送 AI」。
- 會議助理應該預設成全體參與者可見、可理解、可控制、可停止、可刪除、可稽核的系統。
- 不要把「有些法域可能一方同意」理解成「產品可以默默錄」。會議逐字稿、筆記、行動項目和 AI 建議已經是完整個資處理鏈。
- 跨地區產品最保守也最清楚的規格是：明示通知、積極同意、同意證據留存、一鍵停止、一鍵刪除。
- 加州偏全體同意，EU/UK 重點是合法依據、透明度、資料最小化、保存限制和權利行使；台灣、中國、日本、澳洲也不能簡化成一句一方或雙方同意。
- 對學生專題來說，最安全的展示方式是用合成對話、模擬音訊、已同意樣本，不要拿真實敏感會議當資料。
- 技術架構上，最佳方向是本地優先、雲端例外、按鈕觸發、資料最小化。
- 即時轉錄和初步筆記盡量本地處理，只有使用者按下「What should I say?」或「Follow-up questions」時，才送最小必要片段到雲端模型。
- 雲端前最好做遮罩與摘要，不要直接把整段原始逐字稿和可識別資訊送出去。
- Keychain 適合存 API key、資料加密金鑰這種小型敏感資料，不適合塞整份逐字稿。
- 逐字稿和筆記應存加密檔案或加密資料庫，資料加密金鑰由 Keychain 保護；Secure Enclave 比較適合保護特定私鑰或包裝金鑰，不是拿來存任意字串。
- ATS、App Sandbox、最小權限、Hardened Runtime、第三方 SDK 清點都應列為基本安全要求。
- 倫理風險包含監控與權力不對稱、ASR 偏差、LLM 幻覺、錯誤行動項目、資料被濫用或再擴散。
- AI 建議只能是草稿，不能自動替使用者送出訊息、寄信、建立任務或操作外部工具。

## 對專題的影響
- UI 不能只放一個「開始錄音」按鈕，需要開始前同意閘門。
- 浮動面板或主視窗要持續顯示狀態，例如正在轉錄、雲端 AI 開或關、保存政策、由誰啟動。
- 同意不能只是一個總開關，最好拆成錄音、轉錄、雲端建議、資料保留。
- 「What should I say?」按下前可以有微告知，提示將送最近一小段精簡內容到雲端且不會自動發送。
- 若做 BYOK，使用者要知道資料會送到自己選的供應商，供應商條款和保存政策可能不同。
- 一鍵刪除是專題可信度很高的功能，應刪除逐字稿、筆記、快取、搜尋索引，並處理雲端刪除請求。
- 匯出功能要有預覽和遮罩，例如姓名、電話、email、公司名、地址、金額等。
- 若展示用真實人聲，要事前明確取得同意，最好避開健康、法律、成績、財務、未成年人等敏感內容。
- 記錄同意和刪除事件不是官僚流程，而是事後證明 App 沒有亂用資料的依據。

## 可以採用的做法
- 第一版產品規則直接採全體明示同意，即使某些法域可能不用這麼嚴格。
- 開始前對話框說清楚：是否錄音、是否轉錄、是否送雲端、保存多久、誰可以刪除或匯出。
- 會議中固定顯示狀態列：轉錄中、雲端 AI 狀態、保留政策、停止與刪除按鈕。
- 設定「敏感會議模式」：關閉雲端、關閉匯出、會後自動刪除或只保留短期本地資料。
- 雲端建議預設關閉或採按鈕觸發，不要持續把整場會議送到模型。
- 送雲端前先做資料最小化：只取最近 30 到 60 秒摘要、移除明顯 PII、不要附整場逐字稿。
- 儲存分層：API key 放 Keychain；逐字稿和筆記放加密 DB；同意和審計中繼資料另存最小必要欄位。
- 每場會議使用一把資料加密金鑰，金鑰本身由 Keychain 或包裝金鑰保護。
- 所有外部連線遵守 ATS，不任意放寬 TLS 要求。
- 客戶端不要硬編第三方模型主金鑰；公開產品可用後端代理和短效權杖。
- 若是純 BYOK 本機模式，使用者自己的 key 仍只存 Keychain，並且不進 log。
- 同意紀錄至少記錄會議 ID、開始停止時間、啟動者、同意文案版本、錄音/轉錄/雲端/保存開關、刪除和匯出事件。
- AI 輸出標示為建議或草稿，行動項目旁邊保留 evidence turn ids 或來源片段，方便檢查。
- 專題 demo 優先用合成腳本和已同意樣本資料，匯出檔標記為展示資料。

## 風險與待確認
- 這份研究不是正式法律意見，若未來真的上線到多法域，要找法律專業確認。
- EU、澳洲、台灣、日本、中國等地的適用規則都依情境變化，尤其是校園、職場、醫療、法律、未成年人。
- 使用者即使勾選「已取得同意」，實務上仍可能沒有真的通知所有參與者，產品只能降低風險，不能完全消除。
- 雲端供應商的資料保存、訓練、刪除政策要逐一確認，不能只相信「我們不保存」的簡短說法。
- PII 遮罩可能漏掉專有名詞、暱稱、語音中透露的身份資訊，不能當成絕對匿名化。
- ASR 對口音、語言混用、背景噪音的錯誤可能造成不公平或錯誤行動項目。
- LLM 可能把討論中的假設寫成決議，或把沒有指定負責人的事情硬指定給某人。
- 如果開放外部工具或 MCP，提示注入和越權操作風險會變大，必須加使用者確認和審計。
- 學生專題最容易忽略的是刪除、匯出、日誌和權限說明，這些其實比模型效果更容易被審查。
