# 會議筆記與行動項目格式設計 筆記

## 重點整理
- 會議筆記不應只有一種畫面，最好分成「會中即時重點」和「會後正式整理」兩種呈現。
- 即時重點是為了降低當下認知負擔，不需要非常完整；會後紀錄才需要完整、可分享、可追蹤。
- 標準章節可以固定成：TL;DR、主題、決策、行動項目、待釐清問題、風險 / 阻礙、後續追蹤。
- 決策和行動項目一定要分開。決策是已經定案的結果，行動項目是未來要做的事。
- 行動項目不能只是一句話，至少要有負責人、期限、脈絡、狀態。最好再加證據片段、信心分數和外部同步狀態。
- 行動項目一開始應該是 `Proposed`，不要直接變成 `Assigned` 或同步到外部工具，因為逐字稿和抽取都可能錯。
- 筆記內容要能回到逐字稿證據。使用者看到任務或決策時，應該可以點回原本說話片段。
- 只用 LLM 對整場會議做摘要不夠穩，因為容易漏掉負責人、期限、模糊承諾，也比較難解釋。
- 比較好的管線是：ASR / 說話者 -> 語句和主題切分 -> 候選決策 / 行動項目 -> 欄位擷取 -> 信心分數 -> LLM 正規化。
- 即時筆記應該保守，顯示候選重點和候選任務即可；會後再做去重、補脈絡、統一格式。
- 互動式聊天框應該基於逐字稿和筆記證據回答，不應是沒有來源的自由聊天。
- 「追問問題」按鈕可以根據目前缺少的 owner、deadline、成功標準、阻礙、待確認假設來產生。
- 不同會議情境需要不同模板，例如專案會議、客戶訪談、面試、課堂研究討論、站會。

## 對專題的影響
- 我的 App 不必一開始就做很華麗的長摘要，反而應先把行動項目和決策格式做穩。
- 側邊欄可以分成 Live Notes 和 Next Actions，讓使用者會中就看到正在形成的重點。
- 會後輸出可以是比較完整的 Markdown 筆記，方便展示和匯出。
- 行動項目要有確認流程，使用者確認後才進入可執行狀態。
- 外部同步例如 Jira、Notion、Calendar、Email 都應該放在使用者確認之後，不應自動寫入。
- 如果 speaker 分離錯，行動項目的 owner 很容易錯，所以資料模型要把「說話者」和「任務負責人」分開。
- 成功標準不只是摘要漂亮，而是使用者是否少花時間整理、是否能相信任務和決策。

## 可以採用的做法
- 會議筆記輸出固定使用這個格式：
  - TL;DR：3-5 句。
  - 主題：每個主題附時間範圍。
  - 決策：已定案內容、狀態、證據。
  - 行動項目：任務、負責人、期限、脈絡、狀態、信心。
  - 待釐清問題：需要會後補問的地方。
  - 風險 / 阻礙：依賴、卡點、合規或資源問題。
  - 後續追蹤：要寄信、開會、分享文件、同步任務的事項。
- 行動項目物件至少保留：
  - `title`：可執行的任務句。
  - `owner`：人名或 unknown。
  - `deadline`：日期或 unknown。
  - `context`：為什麼要做、和哪個主題相關。
  - `status`：Proposed / Confirmed / In Progress / Blocked / Done / Deferred。
  - `confidence`：抽取信心。
  - `evidence_segment_ids`：回指逐字稿。
  - `sync_state`：是否已匯出。
- 決策物件可以有：`decision_text`、`status`、`topic_id`、`evidence_segment_ids`、`confidence`。
- 即時 UI 裡低信心項目不要進主筆記，只放在「可能的任務 / 待確認」區。
- 信心門檻可以先用產品規則：
  - 高信心：插入筆記，但仍標示為候選。
  - 中信心：放檢閱區，要求 Confirm / Edit / Dismiss。
  - 低信心：不主動顯示，只能搜尋或聊天問到。
- 證據視窗要包含前後幾句，避免只截到一句造成誤解。
- 專案會議模板要特別強調 milestone、dependency、owner、deadline、risk。
- 客戶訪談模板要強調客戶目標、痛點、反對意見、需求、商務後續追蹤。
- 課堂 / 研究討論模板要強調假設、證據、閱讀資料、實驗設計、待查引用。
- 評估方式可以包含：行動項目 precision / recall、owner 準確率、期限正規化準確率、使用者編輯次數、確認率、匯出率。

## 風險與待確認
- LLM 可能把討論中的想法誤寫成已定案決策，所以決策要有較高門檻和證據。
- 代名詞和省略很常見，例如「那我來弄」需要上下文才知道是誰、弄什麼。
- 中文會議裡日期常是「下週三」「這週五前」這類相對時間，需要會議日期才能正規化。
- 行動項目過度擷取會增加清理負擔，甚至比漏掉更讓使用者不信任。
- 即時筆記如果更新太頻繁，可能干擾使用者；應該用短暫提示和側邊欄，不要一直改主內容。
- 會議錄音、逐字稿和筆記都很敏感，要提供本地模式、保留設定、刪除機制和明確狀態。
- 中文 / 英文 / 中英混合的模板和抽取規則可能需要分開調整。
- 自動評估摘要品質不可靠，最後還是要有人評完整性、忠實性和可用性。
