Motivation

會議當下的問題，不只是在會後摘要

線上會議中，使用者要同時聽懂內容、整理回應、避免過度承諾，還要記住決策與下一步。 現有 AI 會議工具多聚焦錄音、轉錄與會後整理；emeet 聚焦正在會議中「下一句該怎麼說」與「接下來該問什麼」。

  • 即時理解目前對話。
  • 產生自然、保守、可說出口的回覆。
  • 把 final transcript 滾動整理成 notes/actions。

Design Consideration

AI 是副駕，不是自動代理人

  • 手動 Start/Stop，讓錄音狀態清楚可見。
  • LLM 呼叫低頻且語意化，避免每 100 ms 跟音訊同頻推理。
  • 只用 final transcript 更新筆記，降低誤寫尚未定稿內容的風險。
  • prompt 明確禁止編造 owner、date、budget、approval 或 commitment。
  • UI 消費 drafts / notes / actions，不解析任意模型 prose。

Implementation

目前已完成的 MVP loop

  • 雙路音訊擷取與音量 meter。
  • PCM16 converter 與 WebSocket STT session。
  • Self / Other 與本機 segment-level speaker numbering。
  • What should I say? 與 Follow-up questions。
  • 30 秒 Meeting Notes / Next Actions 自動整理。
  • SQLite append-first storage 與 Markdown export。

Demo Flow

可展示的端到端流程

  1. Start Meeting。
  2. 顯示麥克風與系統音訊 meter。
  3. 產生 Self / Other transcript。
  4. 按 What should I say? 取得回覆。
  5. 按 Follow-up questions 取得追問。
  6. 整理 notes/actions 並匯出 Markdown。

Known Limits / Future Work

從可 demo 原型走向穩定產品

  • STT 目前是 final speech-window segments，尚非 token streaming partials。
  • RMS VAD 需升級以面對噪音環境。
  • speaker label 是來源與本機分群，不是完整 diarization。
  • 下一版應加入 evidence_segment_ids、rolling summary state 與更完整 privacy mode。
