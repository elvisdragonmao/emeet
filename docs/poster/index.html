Realtime · Local-first · Collaborative Meeting Copilot

emeet

即時會議副駕，把會議對話轉成可說出口的回覆與可同步的文件更新

macOS 原生工具在會議中擷取麥克風與系統音訊，生成逐字稿，並以文件脈絡輔助使用者回應、追問、整理 notes/actions，以及導覽共同編輯中的 Google Docs。

Realtime 會中即時輔助

不是只等會後摘要，而是在對話還在進行時提供下一句回覆與追問。

Local 本地音訊與模型彈性

macOS 音訊擷取搭配本機 STT、Ollama 或 OpenAI-compatible endpoint。

Collaborate 文件共編脈絡

讀取 Google Docs 內容，並把會議 live notes 同步寫回文件。

Prompt 對話提示

使用 What should I say? 與 Follow-up questions 推進討論。

Product Interface

正在會議中：逐字稿、AI 提示與 Google Docs 共編同時發生

1

雙路音訊來源

麥克風用 AVAudioEngine，系統音訊用 ScreenCaptureKit；來源分流讓 Self / Other 標籤更穩定。

2

即時逐字稿

100 ms PCM16 frame 傳到 FastAPI backend，speech-window segmentation 產生可用的 final transcript。

3

對話提示

What should I say? 產生可直接說出口的回覆；Follow-up questions 產生釐清需求、限制、風險與下一步的追問。

4

即時會議紀錄

Meeting Notes 與 Next Actions 使用新增 final transcript 滾動更新，並可匯出 Markdown 紀錄。

5

本地與可替換模型

STT 可切換 faster-whisper / mlx-whisper；助理模型可切換 Ollama、OpenAI-compatible、Codex CLI 與 Copilot CLI。

6

共編與瀏覽導覽

連接 Google Docs 後讀取文件脈絡、更新 live notes，並可透過 Chrome 開啟、捲動或搜尋到指定段落。

Motivation

會議中的關鍵壓力發生在「當下」

線上會議不只需要會後摘要。當對方提出需求、質疑時程、要求文件修改或追問風險時，使用者需要即時理解、回應、追問，並讓共同文件跟上討論。

現有 AI notetaker 多半擅長錄音、轉錄與會後整理；emeet 聚焦把正在發生的對話轉換成可採用的會中行動。

  • 把遠端與自己的發言轉成可讀逐字稿。
  • 把逐字稿轉成下一句話與下一個問題。
  • 把會議重點同步到正在共編的文件。

Core Claim

即時會議輔助的價值來自三件事同步：目前對話、共享文件、下一個可採取的回應。

Design Considerations

降低干擾，同時保留使用者控制

D1 · Separate audio sources
麥克風與系統音訊分流，比先混音再分離更適合即時 demo 與來源標註。
D2 · Match cadence to task
音訊可高頻傳輸；LLM 只在按鈕、筆記週期或文件指令時低頻推理。
D3 · Ground in shared documents
會議經常圍繞文件討論，因此建議與筆記要能參考 Google Docs 脈絡。
D4 · Keep edits bounded
文件修改限定在明確語音指令、可定位段落與單一步驟 batchUpdate。
D5 · Support browser navigation
除了改文件，也要能把 Chrome 導到指定位置，讓使用者與協作者看同一段內容。

Design Outcome

使用者不需要離開會議視窗，就能取得回覆提示、追問方向、文件位置與滾動式紀錄。
