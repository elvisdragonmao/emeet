# emeet Demo 會議腳本

## Demo 主題

討論 emeet 期末展示的產品定位、Demo 流程、海報重點與風險備案。

## Demo 前準備

1. 開啟 emeet。
2. 開啟 Google Docs 文件：`emeet 期末展示規劃`。
3. 在 emeet 中按下 `Start Meeting`。
4. 連接 Google Docs 文件。
5. 確認逐字稿區、Assistant 區、Meeting Notes 區與 Google Docs panel 都看得到。

---

## 第一段：建立會議情境

**Other：**
我們今天先確認 emeet 期末展示要怎麼呈現。你覺得海報上最重要的是放技術架構，還是放實際使用情境？

**Self：**
我覺得不能只放技術架構，因為觀眾可能看不出這個工具實際解決什麼問題。我想用一個 demo 畫面展示逐字稿、回覆建議、追問問題和 Google Docs 共編。

**Other：**
這樣可以。不過你要讓觀眾一眼看出 emeet 和一般 AI 會議摘要工具不一樣。

### 此時按下功能

按下：`What should I say?`

### 預期 AI 回覆建議

可以期待畫面出現類似這樣的建議：

> 我會把重點放在「會議進行中」的輔助，而不是會後摘要。像是使用者可以在會議當下取得下一句回覆、追問問題，並同步更新文件。

或：

> 我想強調 emeet 不是單純的 AI notetaker，而是一個會議中的即時副駕，能在對話進行時幫助使用者反應、整理與修改文件。

**Self 接著照其中一句說：**
我會把重點放在會議進行中的輔助，而不是會後摘要。像是使用者可以在會議當下取得下一句回覆、追問問題，並同步更新文件。

## 第二段：用語音修改 Google Docs 的產品定位

**Other：**
那 Google Docs 裡面現在寫的是「AI 會後摘要工具」，這個說法可能會讓人誤會。你應該把它改成「會議中的即時副駕」。

**Self：**
對，這個定位要改得更準確一點。

**Self 對著麥克風說清楚：**
AI 幫我把「AI 會後摘要工具」改成「會議中的即時 AI 副駕」。

### 此時系統應該做的事

等待 emeet 偵測到語音指令，觸發 Google Docs voice edit。

### 預期 Google Docs 修改結果

`產品定位` 段落中的第一句，應由：

> emeet 是一個 AI 會後摘要工具，主要用來在會議結束後整理逐字稿、產生重點摘要與待辦事項。

改成類似：

> emeet 是一個會議中的即時 AI 副駕，主要用來在會議進行中提供逐字稿、回覆建議、追問問題、會議紀錄與文件共編輔助。

## 第三段：展示 Follow-up Questions

**Other：**
如果你要把它定位成會議中的即時副駕，那 demo 不能只有逐字稿。你要想清楚哪些功能是最值得展示的。

**Self：**
我目前想展示即時逐字稿、What should I say、Follow-up questions、Meeting Notes，還有 Google Docs 編輯。

**Other：**
那你覺得這些功能裡，哪一個最能說明 emeet 的差異？

### 此時按下功能

按下：`Follow-up questions`

### 預期 AI 追問

可以期待畫面出現類似：

> 這次展示的主要觀眾是老師、同學，還是未來使用者？
> Demo 要優先展示「即時回覆」還是「文件共編」？
> 是否需要準備現場失敗時的備用展示流程？

**Self 接著說：**
我覺得最能說明差異的是即時回覆和文件共編。逐字稿只是基礎功能，真正的重點是它能在會議還沒結束前就幫使用者做出反應。

## 第五段：讓 Meeting Notes 自動更新

**Other：**
目前聽起來，海報要強調三件事：第一是即時逐字稿，第二是會中回覆建議，第三是文件共編。技術架構可以放，但不要讓它變成海報唯一重點。

**Self：**
對，我會把海報分成三塊：使用情境、系統架構和 demo 畫面。demo 畫面會放逐字稿、Suggested Reply、Follow-up Questions、Meeting Notes 和 Google Docs 編輯結果。

**Other：**
另外要準備備案。如果現場網路不穩，至少要有錄好的 demo 或截圖。

**Self：**
我會準備一段錄影，也會在海報上放靜態 demo 畫面，避免現場展示出問題。

### 此時按下或等待功能

等待自動 `Meeting Notes` 更新，或手動觸發 meeting notes 更新。

### 預期 Meeting Notes

可以期待畫面出現類似：

> 本次會議討論 emeet 期末展示方式。展示重點應從單純技術架構轉向實際使用情境，特別是會議中的即時回覆建議、追問問題與 Google Docs 文件共編。海報建議包含使用情境、系統架構與 demo 畫面，並準備錄影或截圖作為現場展示備案。

### 預期 Next Actions

可以期待畫面出現類似：

> 調整產品定位文字 — Self — Open
> 補充 Demo 流程說明 — Self — Open
> 準備海報 demo 截圖 — Self — Open
> 準備現場 demo 備案影片 — Self — Open

## Demo 結束後要展示的畫面

最後畫面最好同時看到：

1. 左側或中央有逐字稿，顯示 Self / Other 對話。
2. 右側有 Suggested Reply。
3. 右側有 Follow-up Questions。
4. Meeting Notes 已整理出本次討論重點。
5. Next Actions 有 3 到 4 個待辦事項。
6. Google Docs 已被修改，能看到產品定位與 Demo 流程被更新。

這樣觀眾不用聽完整 demo，也能從截圖中看懂 emeet 的核心價值。
